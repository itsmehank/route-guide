## 추가 (같은 날): 위험 지점 아이콘 · 출발 전 브리핑
### 지도 아이콘
| 예전 | 의미 | 지금 |
|---|---|---|
| `!` 빨간 원 | 사고다발 지점(교통·보행자·어린이·노인·자전거·스쿨존) | 빨간 주의 삼각형 |
| `❄` | 결빙 사고다발 | 파란 삼각형 + ❄ |
| `◉` | 과속 단속카메라 | 카메라 아이콘 |
| `童` / `老` | 어린이 / 노인 보호구역 | 제한속도 표지(빨간 테두리 원 + 숫자) |

카메라·보호구역은 지도를 14레벨 이상 확대했을 때만 보인다(멀리서 경로를 뒤덮던 문제).

### 출발 전 브리핑 (`/briefing.html`, 새 탭)
- 열기: 상세 화면 상단, 경로 비교의 경로별 탭 → "출발 전 브리핑 ↗". 기존 화면은 그대로.
- 서버 `ncp_maps/briefing.py` + `/api/briefing`. LLM 을 새로 부르지 않고, 이미 만든 AI 설명이 캐시에 있으면 곁들인다.
- 체크 지점 = 복잡 분기(진입·진출·분기·유턴·고가/지하차도·옆길) + 톨게이트 + 사고다발 지점, 경로 순서.
- 지점마다 '준비 지점 후보'를 멀리서 가까이:
  - 고속·도시고속화도로의 출구·분기: 2km·1km·500m (예고 표지 일반 배치) — 로드뷰로 실제 표지 확인
  - 일반도로: 300m 방향 예고 표지 · 150m 차로 확정
  - 앞 안내 지점이 가까우면 '‘○○’ 지난 직후'(랜드마크), 150m 이내면 '연속 동작 — 앞 지점 전부터'
  - 진입 직전: 노면 화살표
  - 표지판에서 찾을 방면 이름('서울, 과천'), 옮길 차로 방향을 함께 표시
- 앞 안내 지점보다 먼 후보는 다른 길 위라 만들지 않는다(테스트로 고정).
- 확인 진행률은 브라우저(localStorage)에 저장.
- 테스트: `tests/test_briefing.py` 8개.

### 한계
- 표지판 실제 위치 데이터는 없다. 거리 후보는 일반 배치 기준이고, 로드뷰로 눈으로 확인하는 방식이다.
- 데스크톱 2단 레이아웃은 창 크기를 바꿀 수 없어 브라우저로 확인하지 못했다(모바일 레이아웃만 확인).

## 브리핑 피드백 반영 (2차)
1. **후보 지점 표기:** 숫자(1·2·3) → 문자(A·B·C·D). 체크 번호와 구분. 지도 라벨은 `A 2km 앞` 형태.
2. **구간 설명:** 체크 지점 사이마다 '그냥 따라가는 구간' 카드(출발 → 1번, …, 마지막 → 도착).
   어떤 도로를 몇 km·몇 분 가는지, 그 사이 안내 목록, 다음 지점 준비 시작 거리, 카메라·보호구역 수.
   1km 미만 구간은 "지나자마자 0.2km 만에 ○○가 이어져요"로 줄임. 시간은 guide.duration 누적으로 계산.
   처음 열면 맨 위(출발 구간)부터 보이게 함. 카드의 '지도에서 이 구간 보기'로 해당 구간 강조.
3. **경로와 무관한 위험 지점 제거 (`hazards.on_route`):** 데이터의 radius(사고 선정 반경 200~300m)로만
   붙이던 것을 '경로가 지나는 도로 위'로 다시 거름. 일반도로 50m(카메라 30m, 보호구역 60m) 이내,
   고속·자동차전용도로 위에서는 30m 이내 + 보행자·어린이·노인·자전거·보호구역 유형 제외.
   비교 화면에도 같이 적용됨. 실측: 에잇쿠키 → 화정역 보호구역 16 → 1, 서초초교 어린이 사고(247m 옆) 제외.
4. **HTML 내려받기:** 브리핑 상단 '⬇ 저장'. 파일 하나(지도 이미지 내장, 약 3~4MB)로 인터넷 없이 열림.
   지도는 Static Map 이미지(`/api/staticmap`, 서버 캐시) 위에 경로·체크·후보를 SVG 로 겹침.
   NCP Static Map 레벨은 256px 타일 기준 줌 + 1 (실측 보정). 로드뷰는 파일에 담을 수 없어 설명만 포함.
- 테스트 41개 통과 (`on_route` 3, 구간 2 추가).

## 내려받기에 로드뷰 사진 포함 (3차)
- `ncp_maps/panoshot.py` + `/api/roadview-shot` + `web/pano-shot.html`: 서버가 헤드리스 크롬으로 로드뷰 한 장을 찍어 JPEG 로.
  - `--force-device-scale-factor=1` 필수 — 레티나 배율(2)에서는 창 크기와 그려지는 영역이 달라 아래가 회색으로 비었다(실측).
  - 헤드리스 크롬은 스크린샷을 쓴 뒤에도 종료되지 않는다 → 파일 크기가 멈추면 프로세스를 끈다.
  - 동시 3개, `out/pano_cache/` 에 저장(같은 지점 재사용). 한 장 약 2초·80~120KB.
- 내려받기 HTML: 후보 지점(A·B·C·D)·사고 이력 지점마다 사진 카드(문자·설명 → 사진 → 행동 안내). 휴대폰 폭 레이아웃.
- 실측: 에잇쿠키 → 화정역, 로드뷰 20장 15초, 파일 4.9MB. 크롬이 없으면 사진 자리에 '로드뷰 없음' 표시.
- 로드뷰 사진은 네이버 이미지라 개인 확인용으로만 쓴다(파일 안 안내 문구).

**수정 (`web/js/views/compare.js`)**
- 패널을 구역(브리핑 링크·총평·체크리스트·위험 지점·AI 주의 안내·큰 줄기·근거 사실)으로 나누고 바뀐 구역만 갱신.

  sticky 경로 탭은 기준에서 제외(처음엔 탭이 기준으로 뽑혀 보정이 안 됐다). 브라우저 기본 scroll anchoring 은 끔.
