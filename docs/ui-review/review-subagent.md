# route-guide UI 리뷰 (2026-10-02)

대상: `web/app.html`(1461줄, inline CSS + vanilla JS), `serve.py`, 실행 중인 http://localhost:3000/
방법: 코드 정독 → 기존 스크린샷(`route-guide-screenshots-v2/`) 확인 → Chrome에서 실제 흐름 실행
(죽전역→강남역 결과 확인, 상세보기, 단계 포커스와 로드뷰 말풍선, 경로 비교 결과와 스크롤, 390px 폭은 iframe으로 재현).
`resize_window`는 창이 최대화돼 있어 적용되지 않았고, 대신 390px iframe으로 확인했다. 경유지와 스왑은 기존 스크린샷 05~08로 확인했다.

## 1. 핵심 기능 정의 (코드 기준, 중요도 순)

| 순위 | 사용자 과업 | 코드 근거 | 비고 |
|---|---|---|---|

| 2 | **고른 경로의 실시간 혼잡을 지도에서 확인** | 혼잡 색 구간 992-998, 범례 375-383 | 지도 위 선 색이 사실상 핵심 정보다 |
| 3 | **"어느 길로 갈까" 판단 받기 (경로 비교 + 아버지 서술)** | `openCompare` 1222, `renderCompare` 1253 | 이 서비스의 차별점. 지금은 2~3분을 기다리고 4화면 분량을 스크롤해야 한다 |
| 4 | **헷갈리는 분기점을 출발 전에 로드뷰로 미리 보기** | `focusStep` 1182, `paintFocus` 1095, vantage 조정 1156-1173 | 두 번째 차별점. 상세 패널과 비교 패널 양쪽에서 들어온다 |
| 5 | 턴바이턴 단계 목록 보기 | `openDetail` 1043 | 4번으로 들어가는 입구 역할. 단계 목록 자체만으로는 가치가 낮다 |
| 6 | 경유지 1개 추가 / 출발·도착 바꾸기 / 다시입력 | 1408-1437 | 보조 기능 |

| 8 | 도로 교통량 레이어 토글, 위성 지도 | 1387-1391, `mapTypeControl` 1381 | 부가 기능 |

**결론:** 화면은 "① 경로 고르기 → ② 왜 이 길인지(판단) → ③ 어려운 지점 미리 보기" 세 단계로 짜야 한다.
지금은 ①의 카드에 부가 정보(택시비, 도로 칩)가 많고, ②는 숫자 10행과 장문 서술이 뒤섞여 있으며, ③은 진입 경로가 세 갈래(단계 목록, 말풍선, 비교 버튼)로 흩어져 있다.

## 4. 구조적 문제와 목표 아키텍처

### 현재 구조가 "동적 화면 구성"을 막는 지점

1. **전역 가변 상태가 흩어져 있다.** `state`(420)와 별도로 `map, layers, arrows, labels, endMarkers, focusDot, bubble, pano, vantageNudge, vantageDot, prePano, preBox, cmpData`(421-426, 755, 1208)가 모듈 수준 변수로 있다. 패널이 열려 있는지는 **DOM class로만** 판단한다(`mapPad` 1029-1030, `select` 963, `closeCompare` 1217). 화면 상태를 데이터로 표현할 수 없어서, 화면을 조건에 따라 조합하거나 URL로 복원할 수 없다.
2. **명령형으로 서로를 직접 호출한다.** `select → renderCards + drawAll + fitRoute + openDetail`, `focusStep → paintFocus + openDetail`(1199-1200), `openDetail → closeCompare`(1071), `openCompare → closeDetail`(1224), `go 버튼 → closeCompare + openDetail + focusStep`(1366-1369). 화면 하나를 추가할 때마다 모든 호출 경로를 고쳐야 하고, 그래서 비교 탭과 카드가 어긋나는 문제(2-3)가 생긴다.
3. **innerHTML 문자열 렌더링 후 이벤트를 다시 붙인다.** `renderCompare`는 약 120줄짜리 문자열 조립이고(1253-1372), 렌더 뒤 `querySelectorAll`로 핸들러를 재바인딩한다. 말풍선은 지도 Marker의 HTML 문자열 안에 `id="panoBox"`, `vback` 등을 박고 `setTimeout(0)`으로 바인딩한다(1150). 인스턴스가 하나라는 가정에 묶여 있고, 부분 갱신이 불가능해서(전체를 다시 그림) 스크롤과 포커스가 사라진다. `esc()`가 `"`를 이스케이프하지 않는데(433) title 속성에 넣고 있다(1250).
4. **비동기 요청에 수명 관리가 없다.** `/api/route`와 `/api/compare`에 Abort와 요청 key 검사가 없어서 늦은 응답이 화면을 덮는다(916, 1237).
5. **서버 API가 UI 단계와 맞지 않는다.** `/api/compare`가 지표(즉시) + 위험(수 초) + LLM(분 단위)을 한 번에 돌려줘서 점진 표시가 불가능하다(serve.py 188-235).
6. **한 파일에 성격이 다른 코드가 섞여 있다.** 지오메트리(우측통행 오프셋, Douglas-Peucker, 코너 라운딩 등 약 200줄, 454-673), 로드뷰 예열, 검색, 렌더, CSS 330줄이 한 파일이라 UI 개편 범위를 나누기 어렵다.
7. **레이아웃이 absolute 오버레이 3장이다.** `#detail`(left:312, 330px)과 `#compare`(left:312, 440px)가 같은 자리에 겹치고, 지도 패딩은 매직 넘버로 보정한다(1029-1031). 반응형으로 전환할 슬롯 개념이 없다.

### 목표 아키텍처 (고수준, 기술 선택은 자유)

- **단일 상태 저장소 + 파생 뷰**
  `{ query:{origin, via, goal}, routes:{status, data, key}, selection:{routeId, step}, view:'list'|'detail'|'compare', compare:{status:'idle'|'metrics'|'narrating'|'done'|'error', data, key}, mapOptions:{traffic, type} }`
  모든 이벤트는 action → state 변경 → 구독 컴포넌트 재렌더 흐름으로. `view`와 `query`는 URL(hash/query)에 동기화해서 공유와 새로고침 복원이 되게 한다.
- **컴포넌트 분리**: `SearchForm`, `RouteList`, `RouteDetail`, `ComparePanel`(Summary / Table / Cautions / Hazards), `RoadviewViewer`, `MapView`(route layer, focus layer, hazard layer). MapView는 state만 보고 그리고, 다른 컴포넌트를 직접 호출하지 않는다.
- **레이아웃 슬롯 하나 + 내비게이션 스택**: 좌측 패널(데스크톱) / 바텀시트(모바일) **한 개 안에서** list → detail / compare 화면 전환과 "← 뒤로". 오버레이 패널을 없애면 지도 폭을 확보하고 범례 가림도 해결된다.
- **점진적 비교**: `/api/compare/metrics`(표, 위험, 엔진 판정) 즉시 응답 → `/api/compare/narration`(polling 또는 SSE). UI는 표와 위험 지도를 먼저 보여주고 서술 자리에 skeleton과 경과 시간을 둔다. 결과는 key별로 클라이언트에 캐시한다.
- **파일 분리**: `geo.js`(오프셋, 단순화), `map-layers.js`, `roadview.js`, `api.js`(Abort, key 관리), `components/*`, `tokens.css`. 빌드 없이 ES module로도 가능하다.
- **디자인 토큰**: 타입 스케일(12/14/16/20/24), 색(텍스트 3단계 AA 이상), 간격, 반경, 버튼 4종, SVG 아이콘 sprite.
