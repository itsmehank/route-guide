# [Claude Code Desktop · Cowork] route-guide UI 검토 프롬프트

아래 구분선 사이 내용을 그대로 붙여넣어 실행한다.

---

너는 시니어 프로덕트 디자이너이자 프론트엔드 엔지니어다. 내 로컬 웹 서비스의 UI를 **직접 브라우저로 사용해 보면서** 문제점을 찾아 정리해줘. 코드는 수정하지 마. 결과 문서 1개만 작성한다.

## 대상
- URL: http://localhost:3000/ (이미 실행 중)
- 프로젝트 폴더: `route-guide (프로젝트 루트)`
  - 화면 코드: `web/app.html` (인라인 CSS·바닐라 JS 단일 파일, 빌드 없음)
  - 서버: `serve.py` — `/api/search`(장소 자동완성), `/api/route`(최대 3개 경로), `/api/compare`(경로 평가 + LLM 서술, 수십 초 걸릴 수 있음)
  - 기능 설계: `docs/superpowers/specs/2026-09-11-route-compare-design.md`
  - 기존 스크린샷: `route-guide-screenshots-v2/`, 루트의 `*.png`
- 서비스 성격: 네이버 클라우드(NCP) 지도 기반 자동차 길찾기. 출발/경유/도착 입력 → 경로 카드 3개 → 상세 경로(턴바이턴, 로드뷰) → 경로 비교(비교표, "아버지의 한마디" 서술, 위험 지점).

## 목표 (내가 원하는 방향)
최신 기술로 UX를 개선하고, 화면을 동적으로 구성하고, 가독성을 높이고, **불필요한 내용은 제거하고 핵심 기능에 집중**하고 싶다. 이번 작업은 그 전 단계인 **문제 파악**이다.

## 진행 방법
1. 실제 사용자처럼 아래 시나리오를 브라우저에서 직접 수행하고, 단계마다 스크린샷을 남긴다.
   - 죽전역 → 강남역 길찾기, 경로 카드 3개 비교·선택
   - 상세보기 열기 → 단계 클릭(지도 이동), 로드뷰 앞/뒤 이동
   - 경유지 추가 → 재탐색, 출발/도착 바꾸기, 다시입력
   - "경로 비교" 실행 → 결과가 나올 때까지 기다리며 대기 경험 관찰
   - 위성지도/교통량 토글, 전체경로 보기
   - 검색 결과 없는 장소 입력(빈 상태·에러 상태)
   - 창 폭을 모바일(약 390px)·태블릿(약 768px)으로 줄여 같은 흐름 반복
2. 각 단계에서 다음 관점으로 관찰한다: 첫인상 3초 안에 무엇을 해야 할지 아는가 / 정보 위계와 가독성(글자 크기·밀도·대비) / 시각적 잡음 / 쓸모없거나 중복된 요소 / 패널 간 전환과 겹침 / 지도 영역 대비 패널 공간 / 로딩·에러·빈 상태 피드백 / 키보드·포커스·스크린리더 / 아이콘·버튼 일관성.
3. 필요하면 `web/app.html` 코드를 읽어 원인 위치(라인)를 확인한다.

## 결과물
`docs/ui-review/review-cowork.md` 에 한국어로 작성:
1. **핵심 기능 정의**: 사용자가 이 서비스로 하려는 일 TOP 3~5 (우선순위 순)
2. **화면별 문제점 표**: 화면/컴포넌트 | 문제 | 근거(스크린샷 파일명 또는 코드 라인) | 심각도(상/중/하) | 개선 방향
3. **제거·축소·접기 후보**: 요소 | 이유 | 제안(삭제/숨김/접기/이동)
4. **사용 흐름 마찰 지점**: 시나리오별로 막히거나 헷갈린 순간
5. **모바일/반응형 문제**
6. **Quick win (1시간 이내)** vs **구조적 개선** 목록
7. 스크린샷은 `docs/ui-review/cowork-shots/` 에 저장하고 문서에서 파일명으로 참조

추측은 "추정"이라고 표시하고, 직접 확인한 것과 구분해줘.
